# 项目协作原则模板

这是待填写和评审的模板。先核对目标项目现有规则及工具加载方式，再在授权范围内整合；不要覆盖已有规则。本模板不授予访问、安装、开发、合并、发布或数据传输权限。

## 长期原则

1. 需求连续：维护一个明确的需求基线。新要求作为增量核对，旧未完成项继续保留。部分完成不等于关闭；取消、延期和替代须有决定依据。
2. 先复用：盘点已存在的功能、组件与布局。选择外部方案前检查版本、维护情况、许可和适用边界；先复现最小能力，再做业务定制，不自行更换技术栈。
3. 结果真实：按已评审范围检查身份、对象权限、字段和保存读回。失败、未接通和未实现必须明确显示，不用假成功掩盖。AI 建议与已保存事实分开。
4. 分层验证：构建、接口、持久化、权限、失败恢复和真实 UI 分别记录结果。人工检查主流程、可读性和必要提示；自动测试通过不代替 UI 验收。
5. 可核对交付：把需求、实现、版本和证据对应起来。区分本地、远端与实际运行版本，明确未完项。未部署不称已上线，未验收不称正式完成。
6. 权限与数据边界：只执行已授权操作；不凭模板推断额外权限。内部证据留在获准环境，外发内容单独检查。凭据与真实业务数据不进入公开仓库。

## 项目配置：使用前核验

- 项目目标、适用目录和现有规则：未填写。
- 需求基线、问题跟踪入口和访问工具：未核验。
- 技术栈、固定版本及须保留的结构：未核验。
- 安装、构建、测试、启动命令及前提：从目标项目逐项核验，未知不执行。
- UI 范围、终端、主流程和验收人：待评审。
- 接口、字段、权限和数据恢复标准：待评审。
- 提交、合并、发布及数据共享边界：按当前授权填写。
- 内部证据位置：只在目标项目获准环境填写，不回传公开库。
